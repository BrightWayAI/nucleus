## Release blockers

1. **Stale Cortex ChatGPT manifest.** The pinned
   `adapters/chatgpt_work/codex-plugin.json` still declares 4.27.0 while
   `.codex-plugin/plugin.json` declares 4.28.0. Both the adapter freshness check
   and ecosystem check fail. Regenerate and publish the owning repository's
   adapter before cutting a successor candidate.
2. **Receipt producer/consumer mismatch.** Cortex `/listen` Step 1.5j writes
   `outcome: "succeeded"`. Ops `/register-schedules` Step 5 specifies
   `outcome: "success|partial|skipped|failed"`; `/status` accepts
   `status: "succeeded"` or `outcome: "success"`. A receipt following Cortex's
   example does not satisfy the status reader. Error fields also differ:
   `error_code` versus `error_codes`. Cortex's success example omits `host_id`,
   which matters when multiple hosts share a config root.
3. **Receipt lifecycle is incomplete.** Step 1.5j runs before archive indexing,
   note mining, staging, and hot-cache refresh. Later failure can leave an apparent
   success receipt. Existing-archive and other early exits can bypass it. Move
   terminal receipt finalization to the end and cover failure/skip paths; test
   missing/read-only roots and a failure after brief mining. A shell non-zero exit
   alone is not proof that an agent scheduler records a failed run.
4. **Codex binding verification is not mapped.** The ops command now hardcodes
   Cowork's device/folder arguments, `list_triggers` response shape, and Claude UI
   repair instructions; its OpenAI portability file still has only generic
   scheduler availability guidance. The active Codex tool inventory exposes no
   scheduler registration/listing tool. No equivalent live folder-binding API was
   established by official documentation. Treat the binding as unverified, return
   manual definitions when necessary, and never synthesize Cowork fields.
5. **Brief fallback parity is incomplete.** Step 0D0 derives `closed`, `snoozed`,
   `carried`, and `reflection`, but does not fully specify the canonical
   `suppressed` and `annotations` fields. Step 1 filters snoozes using the separate
   `.snooze-ledger.json`, not the newly derived `snoozed` array. Center of Gravity
   reads `## Reflection` in the Markdown twin, not fallback `reflection.one_thing`.
   With state alone and no prior nightly run, those consumers can miss the fallback
   values. The supplied fallback eval expects these outcomes, but the procedure
   does not connect all the writes and reads. Complete and exercise that round-trip.
6. **Later corrections can be stranded.** Cortex preserves the first closures
   file and writes later findings to a `-remine` companion; briefing reads only
   `<date>.closures.json`. Define how the reader incorporates later explicit
   corrections without duplicating or discarding decisions.
7. **Live certification is missing.** The candidate has no connector evidence for
   the required Claude/operator and ChatGPT/operator profiles. Keep the existing
   host-neutral requirements; do not weaken them to label this a Codex-only release.

The workflow findings above are source-contract analysis, not results of executing
the nightly job or its natural-language evals. Plugin fixes belong in the plugin
repositories. This candidate intentionally pins the requested published commits;
Nucleus documentation does not patch the installed plugin behavior.

## What ports and what does not

| Contract | Finding |
|---|---|
| Config-root resolution | Shared precedence still holds. A pointer locates a root; it does not grant filesystem access. |
| Receipt path | Both published writers use `plugins/ops/schedule-runs/<schedule>/<run-id>.json`. The handoff's `memory/staged/queues/receipts/` path did not ship. No migration is needed to preserve the actual path. |
| Local brief state | OpenAI chat actions still use the canonical v0.7.0 state file and stable item IDs. Missing artifact support does not prevent reading this file. |
| `.artifact-runtime.json` | An additive locator for hosted state, not an OpenAI tool binding or authorization token. It lacks provider/tool identity and conflict handling for newer local state. |
| Hosted readback | Use only an available authorized capability. Without one, disclose missing readback and retain local state. Do not invent an artifact database API or overwrite newer local actions. |
| Root failure | Failure metadata can go to an authorized fallback or the run log when the root is unwritable. Actual scheduler failure propagation still needs host testing. |
| Healthy scheduled loop | Requires a terminal successful receipt less than 26 hours old for the same host/task, plus verified live binding. Scheduler success or cached registration alone is insufficient. |

OpenAI's [scheduled-task documentation](https://learn.chatgpt.com/docs/automations?surface=app)
describes desktop project/worktree execution, the need for the computer and app to
remain available, and the absence of Scheduled management in Codex CLI. It does not
document Cowork-compatible `derived_state.folders_state` fields. This is evidence
for local execution support, not certification of a programmatic binding check.

A read-only inspection of local Codex automation metadata showed an existing task
configured for local execution with working directories. That is configuration
evidence only; no task was changed or run, and no live folder binding was verified.
Private paths, task IDs, and prompts are intentionally omitted here.
